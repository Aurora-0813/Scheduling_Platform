## 三、技术亮点

### 3.1 令牌轮换：并发安全 + 宽限期（**兼顾安全与体验**）

**问题**：`refreshToken` 只在过期时失效的设计有致命缺陷 —— 登出后旧令牌仍能换新令牌。
但直接改成「一次性令牌」又会误伤前端：多个并发请求同时收到 401 时，
每个都会去刷新，只有第一个成功，**其余请求把用户挤下线**（这是最容易引发差评的一类 bug）。

**方案**：Redis 白名单 + 轮换 + **60 秒宽限期**。

| 机制 | 实现 |
| --- | --- |
| 白名单 | `auth:rt:{userId}:{jti}`，未登记即拒 |
| 轮换原子性 | Redis `MULTI/EXEC` 内 `GET + DEL`（内存实现靠「检查与写入之间无 await」） |
| 宽限期 | 旧 jti 换新后 60 秒内可再换**一次**，`GETDEL` 语义**不可重放** |
| 强制下线 | `auth:urt:{userId}` 集合 + 版本号递增 |

**验证**：`test_concurrent_rotation_only_one_wins` 起 5 个并发刷新，
断言**恰好 1 个成功** —— 竞态一旦存在，重放防线就形同虚设，所以这条必须有。

### 3.2 幂等迁移（**在无法确认现状时唯一安全的做法**）

**问题**：Alembic 已建了 9 张表，但是 `开发流程.md` 6.6 要求的 **10 个索引一个都没有**，
ORM 模型也没声明索引。而云库当前**不可达，无法确认它的索引现状**。
直接写 `CREATE INDEX` 的风险是：若云库已经有某个索引，迁移会失败。

**方案**：迁移**先查 `information_schema.statistics`，存在则跳过**。
无论云库现状如何，执行都安全。同时：

- 模型补 `__table_args__` —— **防止下次 `autogenerate` 把这 10 个索引当「多余对象」生成 `drop_index`**（这是最危险的：索引丢了性能塌方但不报错）；
- `downgrade` 做存在性预检（MySQL 的外键自动索引名与目标名不一致，直接 `DROP` 会报 `Can't DROP`）；
- 离线 `--sql` 模式拿不到 `information_schema`，降级为无条件 `CREATE INDEX` 并**输出警示注释**（有测试钉住，且注明离线 SQL 只用于评审）。

### 3.3 权限归一化的极端容错（`normalize_permissions`）

`sys_role.permissions` 是 `JSON` 类型字段，**任何模块都可以往里写**。
一旦有人手抖写了个逗号分隔的字符串、或把权限存成 `{"order:view": true}` 的位映射，
严格的解析会让整个角色 403 甚至接口 500。

**方案**：`normalize_permissions()` 接受 **21 种存储形态**并按同一个语义归一 ——
JSON 数组、JSON 文本、权限位映射、裸字符串、逗号 / 全角逗号 / 分号 / 空格分隔……
**核心判据是「能不能识别出权限码」，而不是「格式对不对」**。
`test_normalize_permissions_handles_every_stored_shape` 用 21 条参数化用例逐一钉住。

### 3.4 埋点零侵入 + 故障隔离（**答辩场景下的自保设计**）

模块 4 的 Agent 链路是答辩演示的主角。如果监控埋点因为 Redis 抖动抛异常，
**整个业务接口 500** —— 那是本末倒置。

**方案**：纯 ASGI 中间件 + 三重保护：

1. 所有 Redis 操作异常全吞（只记 WARNING）；
2. `REDIS_SOCKET_TIMEOUT=0.5` 短超时；
3. 读失败回落到内存镜像，且**不低估**已有计数（回落后指标仍反映本进程真实流量）。

**验证**：`test_broken_metric_store_does_not_break_business_endpoint`（注入一个每个方法都抛异常的指标存储，业务接口仍 200）+ `test_broken_metric_store_does_not_break_monitor_endpoint`。

### 3.5 离线测试体系（**CI 不需要任何密钥**）

云库、Redis、大模型在当前环境下**全部不可达**。若测试依赖它们，
「测试通过」就变成一个无法复现的断言。

**方案**：

| 依赖 | 替身 |
| --- | --- |
| MySQL 云库 | SQLite 临时**文件**库（不是 `:memory:` —— 要验证「未提交的写入在另一个连接里查不到」，内存库下做不到） |
| Redis | `FakeRedis`（含 pipeline / GETDEL / TTL 最小实现） |
| 环境变量守卫 | 在**任何 `app.*` import 之前**设置，并用模块级断言保证顺序被破坏时**收集期直接报错** |

**直接收益**：CI **不需要配置任何密钥**（不需要 `.env`、云库、Redis）。
**代价**：真行锁语义等必须在云库上人工验证 —— 已如实列入未覆盖清单与 `docs/deploy.md` 4.5。

### 3.6 用测试钉住「已知限制」而不是静默修掉

**本轮发现 7 项跨模块或框架级的行为边界**（见第五节）。
处理方式一律是：**写成带 ⚠️ 说明的断言钉住 + 列入待确认项**，而不是顺手改掉。

**理由**：这些都是**跨模块契约或框架结构**决定的行为。
静默「修」会让前端按旧假设写好的代码在联调当天失效；
钉住 + 记录则让「当前行为是什么」有据可查、改动时有测试报警。
