## 一、`database.py`：团队基线 + 两处临时补丁

**取团队版为主体**：`async_engine` / `sync_engine` / `AsyncSessionLocal` / `SyncSessionLocal`、
绝对导入 `from app.core.config import settings`、连接池参数 `pool_size=5` / `max_overflow=10` /
`pool_pre_ping` / `pool_recycle=3600` / `echo=settings.DEBUG`（SQLite 下自动跳过池参数）。

**保留的两处临时补丁**（均已在代码里打 `[临时补丁 N/2]` 标记）：

| # | 补丁 | 用途 | 移除条件 |
|---|---|---|---|
| 1 | `PK_TYPE = BigInteger().with_variant(Integer, "sqlite")` | SQLite 只有 `INTEGER PRIMARY KEY` 是 rowid 别名才自增；`BIGINT PRIMARY KEY` 不会，§13.1 应急镜像库与全部单测都跑在临时 SQLite 上 | 集成组在公用基线给出等价方案后 |
| 2 | `patch_asyncmy_ping()` + 导入时接线 | 修 `MySQLDialect_asyncmy` 继承 pymysql 的 `do_ping()` 却去 introspect **pymysql** `ping` 签名，最终无参调用 asyncmy 必传参的 `ping` → 连接**复用**时 `TypeError`（现象为同接口 200/500 交替） | 集成组在公用后端修好后，删除该函数与接线，回归团队原样 |

两处补丁**都不改变本模块对团队的对外接口**：排除了 `PK_TYPE` 与 ping 包装后，`database.py`
的导出名与语义与团队版一致。补丁 2 已于《docs/公用后端问题反馈.md》第五节反馈给集成组。

## 三、`config.py`：**本轮未改动**（与既定说法不符，见下）

> ⚠️ **这一节与原始纪要的表述不一致，按磁盘实况如实记录。**
> 纪要写的是「基于团队版本修改，修复 `.env` 读取路径问题，新增 `AGENT_URL` 字段」，
> 但**本轮 `config.py` 一个字节都没动**，且「修复路径 / `AGENT_URL`」这两件事
> **是本地版原本就有的设计，不是从团队版改出来的**。团队版反而没有它们。

**当前实况**：`app/core/config.py` 仍是**本地版**，相对团队版有三处实质差异，且三者互相咬合：

| 项 | 团队版 | 本模块现状 | 差异是否 load-bearing |
|---|---|---|---|
| `.env` 定位 | `env_file=".env"`（**相对路径**，按 CWD 解析） | `BASE_DIR / ".env"`（绝对路径） | 是。相对路径下从别的目录启动会**静默读不到 `.env`** |
| 额外字段 | **未设 `extra`** → 按 pydantic-settings 2.5.2 默认 `forbid`，`.env` 多一个键就启动即抛 | `extra="ignore"` | 是。本模块 `.env` 里有 `AGENT_URL`，套团队版会**直接起不来** |
| 本模块扩展 | 无 `AGENT_URL`、无 `DATABASE_URL` 覆盖 | 两者都有 | 是。`AGENT_URL` 是 Agent 联调入口；`DATABASE_URL` 覆盖是 §13.1 SQLite 应急路径的唯一开关 |

**为什么没有一并取团队版**：`config.py` 与 `.env` 是**成对约束**——《比对报告》第三节已列明。
只换 `config.py` 不换 `.env`，`Settings()` 会在 `extra='forbid'` 上直接抛错；只换 `.env` 不换
`config.py`，又拿不到 `AGENT_URL`。要真正对齐，须与集成组确认 `.env` 的**权威键集合**后成对替换，
不是本模块单方面能定的。

**待办**：
1. **`extra` 校验规则的对齐**顺延到下一轮迭代（与上条同一件事）。
2. **`AGENT_TIMEOUT` 待确认**：当前全仓不存在该配置，`agent_client._post_json()` 里
   **硬编码 `timeout=5.0`**。真实 Agent 服务的响应时限需要徐川（模块 4）给定后再落成配置项。
3. `.env` 读取路径与 JWT 相关键位，随认证模块的接入一并复核。

以上三项已收进第八节跟踪表（第 7、8 条）。
