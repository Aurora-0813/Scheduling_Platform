### 5.1 偏离的性质说明

这不是"忘了提交"，而是**两条规则相撞**：

- 一条规则说：`docs/spec/` 是个人工作文档（计划书、阶段任务书、完成文档），不进最终代码
- 另一条规则说：完成文档是本模块交付物，要用于 M4 复现与答辩溯源

两条都成立，于是完成文档的定位自相矛盾：**要么它是工作文档（那就不是交付物，第 9 项应从交付物清单移除），要么它是交付物（那就得单独入库，不能跟着 `docs/spec/` 一起被忽略）。**

### 5.2 三个可选处置（待项目群裁定）

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A. 维持现状 + 修正定义 | 承认完成文档是工作文档，把第 9 项从交付物清单移出，改列为"内部过程记录" | 答辩溯源少一份证据链，需另找替代（如答辩 PPT 引用本地文档截图） |
| B. 单独放行 | `.gitignore` 增加否定规则：`!docs/spec/done/`，只用完成文档入库，计划书与任务书仍忽略 | 需要处理"目录被忽略但子路径放行"的 git 语义，`docs/spec/` 的忽略写法要相应调整 |
| C. 移出该目录 | 完成文档改放 `docs/completion/`，与工作文档分离 | 需同步改 `README.md`、模板与已写的 3 份文档路径 |

**本模块暂定 B，待项目群裁定追认**：完成文档的证据价值正是"给他人看"，留在本地等于没有；而计划书与阶段任务书确实属于个人过程材料，不必入库。

**2026-09-27 补充**：方案 B 于阶段 3 完成文档生成时**提前落地**（`.gitignore` 已改为 `docs/spec/*` + `!docs/spec/done/`，5 份完成文档一次性入库），**项目群裁定尚未追认**。若裁定推翻，回滚 `.gitignore` 即可——放行规则只有两行，不涉及任何已入库的代码文件。

落地时确认了本节表中「需要处理 git 语义」那一条的**具体形态**：`.gitignore` 必须写 `docs/spec/*` 而**不能**写 `docs/spec/`。父目录被整目录排除后 git 不会进入该目录，`!docs/spec/done/` 匹配不到任何文件，白名单静默失效（已用 `git check-ignore` 实测）。
