## 9. 经验与可复用产出

1. **mock 数据要做成「一份三用」并写进文件头。**
   前端屏 3 渲染、40 秒回放、13.1 应急预案要的是同一份数据。
   如果各写各的，字段对不上时是**三处同时崩**。文件头已写明这层关系。

2. **「字段一致」这件事不要靠人眼比对。**
   `_load_mock()` 每次请求都过一次 `ScheduleData.model_validate`，
   字段名写错、缺 `step`、`timestamp` 格式不对，第一次访问就以明确错误暴露，
   而不是把错数据发给前端——前端会照着错数据写出错渲染代码。

3. **mock 路由要做成「不存在」而不是「拒绝」。**
   `if settings.DEBUG` 写成运行期判断（或抛 403）等于承认「有这么个端点，只是不让你用」。
   用导入期条件 + 局部 import，`DEBUG=false` 时连模块都不加载。

4. **应急预案可以比文档写的更简单。**
   13.1 原文的「切换本地 SQLite 镜像库」引入了新依赖与合规冲突，
   而前端按预置 trace 回放已能完整覆盖同一个演示诉求。
