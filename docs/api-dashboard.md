## 通用说明

统一响应体（《规范》5.2）：

```json
{
  "code": 200,
  "message": "ok",
  "data": {}
}
```

- 所有接口以 `/api/v1/` 开头
- 请求头统一 `Content-Type: application/json`
- 时间格式 `YYYY-MM-DD HH:mm:ss`，布尔值用 `true` / `false`
- 下文接口契约中 `→` 之后一律指 `data` 字段内容

## GET /api/v1/dashboard/stats

场地使用率、设备闲置率、预约高峰时段、设备故障频次四项统计。

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| days | int | 否 | 统计窗口天数，默认 `7`，范围 `1`–`90` |

> ✅ **`days` 已生效**（2026-09-27）。传入 `?days=30` 会真实按 30 天统计。
> 越界（`0`、`91`、`-1`）或非整数（`abc`）由框架参数校验拦下，返回 **422**，
> 不会被静默忽略。
> 约束可在 `/docs`（OpenAPI）中直接看到：`default=7, minimum=1, maximum=90`。

### 响应示例

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "spaceUsageRate": 85.5,
    "deviceIdleRate": 20.1,
    "peakHours": [{"hour": 14, "count": 5}],
    "faultFrequency": [{"deviceName": "投影仪A", "count": 3}],
    "degraded": false
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| spaceUsageRate | float | 场地使用率，百分比浮点数（0–100） |
| deviceIdleRate | float | 设备闲置率，百分比浮点数（0–100） |
| peakHours | array | 按小时统计的预约次数，按 `count` 降序；元素为 `{hour, count}` |
| faultFrequency | array | 按设备统计的维修工单数，取 Top 10；元素为 `{deviceName, count}` |
| degraded | bool | 本次是否走了降级路径。`true` = 上面四项均为**占位零值**，不是真实统计结果 |

> 🔔 **契约变更（2026-09-28，需前端知悉）**：`degraded` 是本接口**新增的第 5 个字段**，
> 与 `/report` 的同名字段语义一致。它**追加在末尾**，前四个字段的名称与顺序一个没动 ——
> 按顺序取值的解析不受影响。**不在《规范》5.3 原始契约内**，属模块 8 扩展字段。
>
> 前端只需做一件事：`degraded === true` 时把四张图显示为「数据暂时不可用」，
> **而不是渲染成 0%** —— 那会把「读不到库」误报成「场地全空着」。

### degraded 字段语义

| 值 | 含义 |
| --- | --- |
| `false` | 数据库可达，四项均为真实统计结果 |
| `true` | 数据库不可达，四项为**占位零值**（`0.0` / `0.0` / `[]` / `[]`） |

> 这是《规范》13.1 演示应急预案的一部分：演示时库一断，看板不该整屏空白或报错。
> 与 `/report` 的降级**判定依据不同** —— `/report` 的 `degraded` 还包含 LLM 不可用等情形
> （见下文），本接口没有 LLM 环节，`degraded` 只表示数据库取数失败。

### 错误码

| code | 场景 |
| --- | --- |
| 200 | 成功，**含降级成功** |
| **401** | **未携带 token / token 无效或过期**（待接，见文末「未决事项」） |
| 422 | 参数校验失败（`days` 越界或非整数）；响应体为框架标准校验错误，非统一响应体 |
| 500 | 服务器内部错误（**不含数据库不可达** —— 那种情形已降级为 200，见下） |

> ✅ **数据库不可达时本接口返回 200 + `degraded: true`**（2026-09-28 落地，原为返回 500）。
> 实测响应体：
>
> ```json
> {"code":200,"message":"ok","data":{"spaceUsageRate":0.0,"deviceIdleRate":0.0,
>  "peakHours":[],"faultFrequency":[],"degraded":true}}
> ```
>
> 降级时**字段集合不变**（仍是 5 个）—— 前端不需要为降级写第二套解析。
> 失败详情只记在后端日志（`logger.exception`，带完整堆栈），不通过接口外泄。
>
> 上表仍保留 500 一行：其他未预期异常（代码缺陷等）依旧是 500 ——
> 这里降级的是**已知的、可预期的**取数失败，不是把所有异常都吞掉。

## GET /api/v1/dashboard/report

AI 数据洞察报告，返回结构化建议列表。

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| days | int | 否 | 统计窗口天数，默认 `7`，范围 `1`–`90` |

> ✅ 与 `/stats` 相同：`days` 已生效，越界或非整数返回 **422**。

### 响应示例

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "suggestions": [
      {"finding": "...", "evidence": "...", "suggestion": "..."}
    ],
    "exportUrl": null,
    "degraded": false
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| suggestions | array | AI 建议数组，每条含 `finding` / `evidence` / `suggestion` 三要素，**永不为空数组** |
| exportUrl | string \| null | 报告下载链接，形如 `/static/exports/dashboard_20260927_194500.csv`（**相对路径**，前端需拼上后端 origin，见下）；**数据库不可达**或**写盘失败**时为 `null` |
| degraded | bool | 本次是否走了降级路径 |

### suggestions 三要素

《规范》4.4 模块 8 强制每条建议同时具备三个字段，缺一不可：

| 字段 | 说明 |
| --- | --- |
| finding | 发现的事实，含具体数字 |
| evidence | 数据依据，引用统计结果中的**真实数字**（不编造） |
| suggestion | 可执行的建议动作 |

### exportUrl 怎么用（前端必读）

`exportUrl` 是**相对路径**，不是完整 URL。后端挂在 `/static` 上的静态目录直接提供文件下载，
所以前端不能直接把它塞进 `<a href>`，否则会拼到前端的 dev server 上（Vite 默认 5173）而 404：

已实现在 `frontend/src/api/dashboard.js` 的 `resolveExportUrl()`（此处只讲行为，不重复代码）：

| `request.defaults.baseURL` | 处理 |
| --- | --- |
| 空 | 原样返回 —— 前端 dev server 靠 Vite `proxy` 把 `/static` 转发到后端，同源拼接即可 |
| `/api/v1`（相对前缀） | 同上 |
| `http://localhost:8000`（完整 origin） | 用 `new URL()` 拼成绝对地址 |
| 已是完整 URL | 原样返回（幂等） |

行为约定：

| 情况 | `exportUrl` |
| --- | --- |
| 正常路径（AI 可用） | 路径 |
| 降级路径，但 stats 取到了 | **仍是路径**（降级报告也值得导出 —— 里面有统计表） |
| 数据库不可达（手里没有 stats） | `null`（硬导会得到「统计字段全空」的 CSV，比 `null` 更容易误导） |
| 写盘失败（磁盘满 / 无权限） | `null`，且**接口仍返回 200**，不抛 500 |

> `degraded: true` 与 `exportUrl: null` **不等价**，两者要分开判断 ——
> 第二种情况就是反例（降级了但有链接）。前端导出按钮的 `disabled` 只应看 `exportUrl`。

CSV 内容：表头块（统计窗口 / 生成时间 / 是否降级）+ 四项统计 + 建议表（序号 / 发现 / 数据依据 / 建议动作），
编码 `utf-8-sig`（Excel 双击打开中文不乱码），文件名 `dashboard_YYYYMMDD_HHMMSS.csv`。

> ⚠️ **`exportUrl` 会过期 —— 有效期 7 天**（2026-09-28 起实现自动清理，见下）。
> 所以：
>
> - **不要**把 `exportUrl` 存进数据库 / Pinia / `localStorage` 长期持有，
>   更不要做成「历史报告列表」—— 一周后那些链接全是 404
> - 要展示历史报告就得**重新调 `/report`** 生成一份新的（每次调用都会落一个新文件）
> - 前端拿到链接后立刻用（`<a :href="resolveExportUrl(url)" download>`），这是它的设计用法
>
> 清理策略：保留 **7 天**（按文件 `mtime` 判定），两处触发 ——
> **每次生成报告前**顺手清一次 + **服务启动时**清一次。
> 只清理本模块生成的 `dashboard_*.csv`，同目录下别的东西（同事调试放的文件）不动。
> 清理失败（文件被 Excel 占用等）只记日志，**不影响本次报告生成**。

### degraded 字段语义

| 值 | 含义 |
| --- | --- |
| `false` | 大模型正常返回，建议由 AI 生成 |
| `true` | 走了降级路径，建议由**纯统计模板**生成 |

触发 `degraded: true` 的情形：

1. 未配置 `LLM_API_KEY`
2. 大模型调用超过 8 秒超时
3. 大模型返回内容无法解析为合法 JSON（三层容错全部失败）
4. 解析成功但三要素不全
5. **建议引用了统计结果以外的数字（业务边界校验未通过，判定为幻觉）** ——
   全部建议都被判定为幻觉时走降级；部分通过时只丢弃有问题的那几条，
   此时 `degraded` 仍为 `false`

> 前端建议据此显示提示，例如 `degraded: true` 时在建议区标注「AI 暂不可用，以下为统计结果」。
> 该字段同时是《规范》13.1 演示应急预案可验证的前提 —— 答辩时可据此证明降级链路真实有效。

### 错误码

| code | 场景 |
| --- | --- |
| 200 | 成功，**含降级成功** |
| **401** | **未携带 token / token 无效或过期**（待接，见文末「未决事项」） |
| 422 | 参数校验失败（`days` 越界或非整数） |

> **本接口不返回 500**。数据库不可达时同样返回 `code=200`、`degraded: true`，
> `suggestions` 为一条说明数据源不可用的提示（`evidence` 中写真实失败类型，不编造统计数字）。

## 字段命名规则

- 后端传输字段一律采用 `camelCase`（《规范》6.2）
- 数据库表名与字段名采用 `snake_case`，前端不直接接触
- 传输结构由 `backend/app/schemas/dashboard.py` 的 Pydantic 模型定义
  （Python 侧 `snake_case`，通过 `alias_generator` 自动输出 `camelCase`）。
  前端可直接从 `/docs` 或 `/openapi.json` 取到完整 schema，无需依赖本文档手抄
